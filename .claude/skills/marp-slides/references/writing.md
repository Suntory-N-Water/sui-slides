# 文章の書き方

## スライドの文章

- 見出しに主張を書く。「現状について」ではなく「受け取り待ちが 6.4 分に伸びている」のように、見出しだけで結論が分かる形にする
- 1 枚の本文は 3 文までを目安にする。読み上げる原稿はスピーカーノートか別の資料に置く
- 数値は単位と期間を添える。「41%」だけでは比較できない
- 箇条書きの各項目は同じ品詞・同じ長さに揃える。名詞句と文章を混ぜない
- 比喩や飾った言い回しを避け、動作をそのまま書く

## textlint

`pnpm lint:text` が `slides/**/*.md` を調べる。適用しているのは `textlint-rule-preset-ai-words-ja` の 2 つ。

### no-ai-words

AI が書いた日本語に出やすい語を指摘する。形態素解析なので活用形も一致する。指摘されやすいのは、英語の直訳のような動詞と、一般的でない比喩に使う名詞。

```text
効く / 壊れる / 走る / 焼く / 黙って / 〜に落ちる / 崩す / 値を動かす / 〜から引く /
経路 / 死活 / 漏れ / 帰結 / 原初 / 穴 / 無差別 / 正本 / 正典 / 部品 / 検査 /
〜に配線する / 太る / 見張る / 原料 / 実測 / 疑う / 照合 / 見落とす / 突き合わせる /
断定 / 入口 / 土台 / 道具 / 核心 / 構図 / 線引き / 事故 / 混ざる / 落とし穴 /
破綻 / 素通り / 切り分ける / 潰す / 踏み込む / 溶かす / 既定では / 定番 / 定石 /
〜した瞬間 / 静かに
```

最新の一覧は `node_modules/textlint-rule-preset-ai-words-ja/README.md` にある。

言い換えの方向は、比喩をやめて動作をそのまま書くこと。

```text
設定が効く            → 設定が適用される
ボトルネックを切り分ける → どこで時間がかかっているかを分ける
導入の入口をつくる      → 最初に試す範囲を決める
設計の核心           → 設計で最も重要な点
定石どおりに進める      → よく使われる手順で進める
注文した瞬間に通知する   → 注文と同時に通知する
```

どうしても必要な語は `.textlintrc.json` の `no-ai-words.allows` に足す。スライド本文に `textlint-disable` を書くと HTML コメントがスライドに残るため使わない。

### no-short-topic-comma

文頭から 5 文字以内で打つ読点を指摘する（`maxLength: 5`）。主題だけを短く示す言い回しを減らすため。読点を削るか、主題を含めて言い切る形に直す。

```text
結論は、次の3つです。   → 結論は次の3つです。
ポイントは、待ち時間。   → 待ち時間が最も長い工程です。
```

このルールは `true` では適用されない。`.textlintrc.json` のようにオプションを渡す必要がある。

## 用語

- 日本で定着している正式名称か、動作をそのまま説明する平易な日本語で書く
- 英語のまま置くのは、製品名・クラス名・コマンドなど、訳すと参照できなくなるものだけ
